## 7. Mapeo de errores HTTP (módulo compartido de feature)

- [x] 7.1 Crear `frontend/features/reservations/lib/error-mapping.ts` exportando tipos discriminados y un hook `useReservationsError(queryResult)` que mapea un `UseQueryResult` de TanStack Query a una variante tipada: `{ kind: "loading" } | { kind: "forbidden" } | { kind: "not-found" } | { kind: "validation" } | { kind: "error" } | { kind: "ok" }`. Reglas: (a) **`status: 401`**: **no** se renderiza estado localizado —se delega al mecanismo existente de expiración de sesión (`notifySessionExpired` ya invocado por `createAuthenticatedClients` en 3.2 y propagado al `auth-provider`, que limpia tokens y vuelve a `/login`); el hook devuelve `{ kind: "loading" }` mientras el flujo de refresh está en curso o el resultado es indefinido, y si la query termina en `401` se considera "manejada fuera" y el componente queda en `loading` hasta que el redirect concluya; (b) **`status: 403`**: devuelve `{ kind: "forbidden" }`; (c) **`status: 404`**: devuelve `{ kind: "not-found" }`; (d) **`status: 422`**: devuelve `{ kind: "validation" }` **sin payload** —ni `error.message` ni `error.details` se leen, ni se exponen al componente, ni se mapean a nada—. Lista y detalle mostrarán únicamente el texto localizado `t("reservations:fields.validation")`. (e) **5xx o red** (`TypeError`/network): `{ kind: "error" }`; (f) **`ok`**: `{ kind: "ok"; data: ... }`. El módulo **no** contiene strings de UI —sólo la forma de los datos—; los textos se leen de `reservations:fields.*` y `states:*` en el componente. [R5.4]
- [x] 7.2 Crear `frontend/features/reservations/lib/error-mapping.test.ts` con tests unitarios del mapeador (sin React): (a) `ApiError status: 401` no devuelve `forbidden`/`not-found`/`validation`/`error` y entra en la rama de "manejada fuera"; (b) `ApiError status: 403` → `forbidden`; (c) `ApiError status: 404` → `not-found`; (d) `ApiError status: 422` con `message: "cualquier cosa"`, `details: { status: "invalid", property_id: "x" }` y `code: "validation_error"` → `validation`, **sin** exponer `message`/`details`/`code` en la variante devuelta (la variante es exactamente `{ kind: "validation" }`); (e) `ApiError status: 500` → `error`; (f) `TypeError` (red) → `error`; (g) resultado con `data` → `ok` con `data`. [R5.4]
