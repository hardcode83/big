- `infra/environments/dev/variables.tf`: nueva `variable "runner_count"` (`type = number, default = 4`, **amend 2026-09-04** — antes 2) con `validation` `1 ≤ runner_count ≤ 4` — fuente única del número de agentes para el resto del change.
- `infra/environments/dev/main.tf` línea 161: `runner_count = var.runner_count` añadido al mapa de `templatefile()` de `cloud-init.yaml.tftpl` (entre `env` y `github_repo`; los `file()` siguen al final).
- `infra/environments/dev/cloud-init.yaml.tftpl`: la entrada final de `runcmd` (única con quoting, single-quoted YAML para preservar el `$` y `"$RUNNER_COUNT"` literales) es `'RUNNER_COUNT=${runner_count} sudo bash /opt/bootstrap-runner.sh "$RUNNER_COUNT"'`. `runner-bootstrap.sh` debe leer `$1` como `RUNNER_COUNT` (tarea 2.1).
- `infra/environments/dev/runner-bootstrap.sh` sección 2: variables por agente — `RUNNER_USER=actions-runner-<i>`, `RUNNER_HOME=/opt/actions-runner-<i>`, `agent_name=autohostai-${ENV}-vm-<i>`, `svc=actions.runner.${GITHUB_REPO//\//-}.autohostai-${ENV}-vm-<i>.service` (prefijo `SERVICE_PREFIX`).
- `infra/environments/dev/runner-bootstrap.sh` sección 2: source of truth de los agentes numerados = `AGENTS_LIST=/var/lib/autohostai-runner/agents.list` (un nombre por línea, escrito con `mv` desde un `mktemp` al final del bucle de alta — la fase de baja lo lee antes del bucle).
- `infra/environments/dev/runner-bootstrap.sh` sección 2: agente legado = `LEGACY_NAME=autohostai-${ENV}-vm` (sin sufijo numérico), `LEGACY_HOME=/opt/actions-runner`, `LEGACY_SERVICE=actions.runner.<org>-<repo>.${LEGACY_NAME}.service`. La migración se ejecuta ANTES del bucle como Fase 0; si GitHub lo lista vía `GET /repos/{owner}/{repo}/actions/runners`, se retira con `config.sh remove --token $REG_TOKEN && svc.sh uninstall $LEGACY_SERVICE` (el registration-token sirve también para remove).
- `infra/environments/dev/runner-bootstrap.sh` sección 2: API endpoints llamados — (a) `GET https://api.github.com/repos/$GITHUB_REPO/actions/runners?per_page=100` con `Authorization: Bearer $INSTALL_TOKEN` para listar corredores en Fase 0; (b) `GET /actions/runs?status=in_progress&per_page=100` + `/actions/runs/{id}/jobs?per_page=100` para buscar jobs en vuelo de un runner activo (Fase 1, condición de baja abortada). El registration-token (`POST /actions/runners/registration-token`) sigue siendo vía `curl --config` para no aparecer en `argv`.
- `infra/environments/dev/runner-bootstrap.sh` sección 2: gotchas — (1) `INSTALL_TOKEN` se mantiene vivo durante todo el script (no se `unset` tras mintear el `REG_TOKEN`) porque lo reusan los helpers GitHub; se `unset` al final junto con `REG_TOKEN`. (2) El trap ERR por agente usa FUNCIÓN (`on_err`), no string single-quoted — un `'...$step...'` capturaría `step=""` y diría "agent k/N: failed" sin contexto (necesario para depurar). (3) `local` no es válido dentro de la subshell `(...)` del bucle de alta; las variables de paso (`state`, `runner_version`) son subshell-locales sin `local`. (4) El bucle de alta es tolerante a fallos por iteración (tarea 2.5); el surplus phase ABORTA con `set -e` (tarea 2.3). (5) `agents.list` se sobrescribe al final del bucle desde el `mktemp`; en una caída mid-loop, la versión anterior sobrevive y el re-run usa `--replace` para re-registrar lo que ya estaba.
- `infra/environments/dev/runner-bootstrap.sh` (sección 2 review-panel, F1): línea 260 (`for name in "${declared_names[@]:-}"`) cambiada a `"${declared_names[@]+"${declared_names[@]}"}"` — bajo `set -euo pipefail`, `:-` iteraba UNA vez con `name=""` cuando el array estaba vacío, y el cuerpo calculaba `svc=…-vm-.service` que `systemctl is-active` no encontraba, terminando en `retire_named_agent ""` (regex fail → `set -e` abortaba antes de Fase 2). Idem línea 269 para `surplus`. Reproducido con `bash -c 'set -euo pipefail; surplus=(); for name in "${surplus[@]+"${surplus[@]}"}"; do echo "[$name]"; done; echo done'` → imprime solo `done`, sin `[ ]`.
- `infra/environments/dev/runner-bootstrap.sh` (sección 2 review-panel, F2): `gh_list_runner_names` (líneas 82-92) reescrita para enviar `INSTALL_TOKEN` por `printf … | curl --config -` (stdin), mismo patrón que `REG_TOKEN` arriba (línea 72). Antes el `-H "Authorization: Bearer $INSTALL_TOKEN"` ponía el installation-token en el `argv` de `curl`, legible por cualquier usuario de la VM vía `/proc/<pid>/cmdline` (incluido el nuevo `actions-runner-<i>`). `awk` del cuerpo de la función: 0 ocurrencias de `-H "Authorization`; el `Authorization: Bearer` solo aparece dentro del template del `printf`.
- `infra/environments/dev/runner-bootstrap.sh` (sección 2 review-panel, F3): al inicio del cuerpo del `for name in surplus` (líneas 269-273) añadida defensa en profundidad — `[[ ! "$name" =~ ^autohostai-${ENV}-vm-([0-9]+)$ ]]` salta con `WARN` y `continue`. Independiente de F1: si `agents.list` se edita a mano con un nombre que no encaja, no se produce un `…-vm-.service` inválido ni se delega la validación exclusivamente en `retire_named_agent` (que abortaría `set -e` y bloquearía el bootstrap).
