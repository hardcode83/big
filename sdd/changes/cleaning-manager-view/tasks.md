### 12.B — Real stack probe — NO EJECUTABLE EN WORKTREE, registrado y NO BLOQUEANTE

**Limitación documentada (no se implementa nada).** El worktree **no tiene credenciales seed utilizables** para autenticar una petición HTTP real a `GET /api/v1/cleaning-tasks` desde la red interna de compose. Precedent inmediato: `incidents-web` 11.C y `reservations-web` 11.4(a) ya documentaron esto — `make seed-demo` exige `BOOTSTRAP_TENANT_*` y `SEED_*` en `.env`; el `.env` del worktree no las trae.

**Consecuencia explícita**: `docker compose exec -T frontend npm test ...` (12.1) **NO equivale** a un probe real del stack vivo — los tests mockean `HttpCleaningTasksSource` y los hooks, no hacen una petición HTTP real al backend. **Ninguna** tarea de 12.A es evidencia de que el stack vivo sirve las tareas de `make seed-demo`/`seed-data-demo-extension`.

**Sin tarea `[ ]` aquí.** La evidencia de "el stack vivo sirve los seeds" se difiere a staging post-merge y se registra en la recomendación no bloqueante siguiente.

### 12.C — Recomendaciones no bloqueantes (NO son tareas `[ ]`)

> Estas recomendaciones se ejecutan **después** de `mark-local-verified`, en staging post-merge, si el revisor lo considera útil. **Ninguna** es necesaria para `mark-local-verified`: las tareas 12.1–12.6 son la fuente de verdad y se ejecutan dentro del worktree.

- **Smoke visual humano contra staging** con un usuario seed real: la lista carga con las tareas del seed; el filtro `status` cambia la lista; la paginación avanza/retrocede con `totalPages` del backend; el detalle muestra los 16 campos; `property_id` con `<script>` o saltos de línea se ve como texto; `validation_status` se ve con color semántico distinto entre `PASSED` y `FAILED`; `assigned_cleaner_id` aparece bajo una sección secundaria con la nota; los `null` se ven como `—`; un id inexistente muestra "Tarea de limpieza no encontrada" en el detalle y error genérico en la lista; ES/EN cambian los textos (las 9 de `status` y las 4 de `validation_status`).
- **Real stack probe con credenciales reales** en staging, una vez mergeado y con la BD poblada por `make seed-demo`/`seed-data-demo-extension`: `docker compose exec -T frontend sh -c "curl -H 'Authorization: Bearer <token>' http://backend:8000/api/v1/cleaning-tasks | jq '.data | length, .total, .total_pages'"` desde la red interna de compose — confirma que el stack vivo sirve las tareas del seed y que `total_pages` viene en el sobre. La **obtención del `<token>`** requiere un seed completo con `BOOTSTRAP_TENANT_*`/`SEED_*` en `.env`, fuera del scope de este change; se delega a la cadena de staging.
