## Implementation Notes

### Section 1 — batch transition-history reader

- Port signature, verbatim: `async def history_for_properties(self, tenant_id: uuid.UUID, property_ids: Sequence[uuid.UUID], start: date, end: date) -> dict[uuid.UUID, Sequence[PropertyStateTransition]]` — `backend/app/properties/domain/repositories.py:458` (Protocol), adapter at `backend/app/properties/infrastructure/repositories.py:452`.
- `property_ids` is `Sequence[uuid.UUID]`, matching `TimelineEventReader.last_for_properties` (whose return shape this mirrors), not the `Collection` of `ReservationRepository.list_for_properties`.
- `start`/`end` are `datetime.date`, **not** `datetime`: section 3's use case passes `week_bounds(today)` straight through, no conversion of its own.
- Date→instant conversion lives **only** in the adapter: `start_instant = datetime.combine(start, time.min, tzinfo=UTC)`, `end_instant_exclusive = datetime.combine(end + timedelta(days=1), time.min, tzinfo=UTC)`. So `end` is inclusive as a calendar day (Sunday 23:59:59 UTC is in, Monday 00:00:00 UTC is out) and `start` is inclusive from midnight UTC. Section 3 must not pre-convert or add a day.
- Result is **sparse**: a property with neither an entering transition nor one inside the window is absent from the dict — not mapped to `()`. Section 2's `occupancy_series` must treat a missing key as "no transitions" (R2.3), the same as an empty sequence.
- Each present value is a `tuple`, chronological (`created_at`, then `id` as tiebreak), with the one pre-`start` transition first when it exists. Section 2's defensive `sorted(..., key=(created_at, id))` is therefore a no-op in practice, not a correction.
- Empty `property_ids` returns `{}` without touching the database (pinned by `test_history_of_no_properties_does_not_query`).
- Cost is exactly **2** SELECTs against `property_state_transitions`, portfolio-independent — pinned by `test_history_costs_two_statements_whatever_the_portfolio_size` (1 vs 5 properties, counts compared to each other before the literal 2). Section 4.6's endpoint-wide ceiling can count on 2 from this reader.
- R3.3 is pinned structurally by `test_the_transition_port_still_has_add_and_no_new_writer`: it asserts the repository's public surface is exactly `{add, applied_clock_triggers, last_for_property, history_for_properties}` (a whitelist, not a list of forbidden names). **Any later section adding a method to this port or adapter must extend `TRANSITION_REPOSITORY_SURFACE` in `backend/tests/properties/test_repositories.py`.**
- `FakePropertyStateTransitionRepository` (`backend/tests/properties/doubles.py`) was deliberately left alone: it already omits `last_for_property`, so a fake covering only the methods its use case calls is the established precedent here.
- No migration: `ix_property_state_transitions_property_id_created_at` covers the leading keys of both statements.
- The container's pytest rootdir is `/app` = `backend/`, so the working command is `docker compose exec backend uv run pytest tests/properties/test_repositories.py` — **without** the `backend/` prefix.
- `ruff` is not installed in the backend image (`uv run ruff` fails to spawn); `uv run pyright <files>` works and reports 15 pre-existing errors in `test_repositories.py`/`infrastructure/repositories.py` (`reportOptionalMemberAccess`, `Result.rowcount`) that are untouched baseline noise.

### Section 2 — occupied-night domain logic

- `OccupancyPoint` — `backend/app/dashboard/domain/read_models.py:242` (frozen dataclass, at the end of the file, after `PropertyDetail`). Fields, in order: `date: date`, `occupied_properties: int`, `total_properties: int`, `occupancy_pct: Decimal | None`. The field really is called `date` and shadows nothing (`Decimal` was already imported by `FinancialBlock`). Section 4.1's `OccupancyPointResponse` maps these four one-to-one — no colour, no weekday label.
- Everything else lives in the new `backend/app/dashboard/domain/occupancy.py` (165 lines, zero framework imports; `tests/test_layering.py` covers it):
  - `def week_bounds(today: date) -> tuple[date, date]` — `:65`. Both ends **inclusive** (Monday, Sunday). Feed the pair straight to `history_for_properties`, which adds the day itself; **do not** pre-convert or add a day. `week_start` for `occupancy_series` is the first element.
  - `def end_of_day_exclusive(day: date) -> datetime` — `:77`. Midnight UTC of `day + 1`, matching section 1's adapter conversion. Exported (not underscored) because section 4's tests may want the same boundary.
  - `def occupancy_series(week_start: date, active_property_ids: Iterable[uuid.UUID], reservations: Iterable[Reservation], transitions_by_property: Mapping[uuid.UUID, Sequence[PropertyStateTransition]]) -> tuple[OccupancyPoint, ...]` — `:87`. **No `*`**: all four parameters accept positional or keyword, so section 3 can call it either way. No `today` parameter — deliberately; `week_bounds` is the only place `today` is used (D3).
  - `OCCUPYING_STATES` — `:58`, `frozenset({BLOCKED_BY_OWNER, OUT_OF_SERVICE})`, exactly the two states R2.1 names. `OCCUPIED_ESTIMATED` is **not** in it: `state_resolution.py:164-166` derives it from the very reservations this function already counts, so including it would double the calendar's vote. `test_the_occupying_states_are_exactly_the_two_the_requirement_names` pins the set as a literal.
  - `DAYS_IN_WEEK = 7` — `:50`.
- **`transitions_by_property` is sparse, and `occupancy_series` relies on that being harmless**: it reads the mapping with `.get(property_id, ())`, so a property absent from section 1's dict behaves exactly like one mapped to `()` — "neither blocked nor out of service" (R2.3). Section 3 must pass `history_for_properties`'s result through **unchanged**; densifying it into `{id: () for id in ids}` first is allowed but pointless, and `test_a_missing_key_and_an_empty_sequence_agree` pins the equivalence.
- **`active_property_ids` is both the denominator and the filter.** A reservation or a transition whose `property_id` is outside it is ignored, so `occupied_properties` can never exceed `total_properties`; duplicates in the iterable are collapsed with `dict.fromkeys`. It is materialised once, so section 3 may hand it a generator over the property rows.
- **`created_at` must be timezone-aware.** The comparison is against a UTC boundary, so a naive `datetime` raises `TypeError` rather than being silently reinterpreted. The column is `DateTime(timezone=True)` and section 1's adapter returns aware values, so this only bites hand-built fixtures.
- `occupancy_pct` is `(occupied * 100 / total).quantize(Decimal("0.1"), rounding=ROUND_HALF_UP)` — `ROUND_HALF_UP` to match `app/pricing/domain/calculator.py`, not `Decimal`'s banker's default (2/3 → `66.7`). `None` **only** when `total_properties == 0`, and then on all seven points; an occupied-nothing day of a real portfolio is `Decimal("0.0")`, not `null`. Section 4.1's schema must keep those two apart on the wire.
- D3's end-of-day snapshot is load-bearing and mutation-checked: flipping the boundary to `<=`, dropping the defensive `sorted(..., key=(created_at, id))`, and swapping the snapshot for any-instant overlap each turn the suite red (1, 1 and 4 failures respectively). `test_a_same_day_block_and_release_does_not_surface` is the accepted-consequence test — anyone "fixing" it is reopening a decision the user confirmed at the design gate of 2026-09-02, not correcting a bug.
- Verified: `docker compose exec backend uv run pytest tests/dashboard/test_occupancy_series.py -v` → **47 passed**; `uv run pyright` on the two new/changed `app/` files plus the test file → **0 errors**.
