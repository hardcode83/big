  - **How the "changed" boolean crosses the subshell boundary** (the reason for the placement): `write_runner_env` prints exactly one word on stdout — `changed` or `unchanged` — with every diagnostic on stderr. Both helpers are called from the **main script body**, inside the Fase 2 registration loop right after `register_named_agent "$i"` succeeds (same gate as `registered_idx+=("$i")`), NOT from inside `register_named_agent`'s subshell: a `( … )` subshell cannot hand a variable back to its parent, and the restart decision needs that value later in the same scope. The word is captured into `hook_state` and, when `changed`, the index is pushed onto a new `env_changed_idx=()` array. The start loop then converts that array to a plain `0`/`1` and passes it to `start_named_agent "$i" "$env_changed"` as a **second positional argument** — that direction (parent → subshell) is free, and nothing has to come back out.

The `failed|inactive|unknown)` branch is unchanged and needs no restart — the process is born after the `.env` is written. A failure of the hook install/declaration itself does NOT abort the loop (same per-agent tolerance as the rest of Fase 2) but does set `had_failure=1`.
